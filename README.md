# Голосовой помощник для ИИ-агента

Локальный сервис, который умеет **произносить голосом** то, что агент
хочет сказать человеку. Работает без интернета и без платных сервисов.

Агент формулирует фразу, отправляет её в сервис, получает звуковой файл
и озвучивает его. Или просто вызывает одну функцию — и фраза звучит.

```
"Проверка закончена, всё работает."
        │
        ▼
   голосовой сервис  ──▶  ozvuchka/IRINA.wav
   (127.0.0.1:18905)         ▶  звучит
```

---

## Что это решает

Текстовый отчёт агента лежит в файле, и его читают тогда, когда дойдут
руки. Часто — не читают вообще. Голосовое сообщение нельзя «не услышать»:
оно звучит, в нём называется, кто говорит, и оно заканчивается конкретным
фактом.

Короткое сообщение в пять–десять секунд дослушивают целиком. Минуту не
дослушает никто. Поэтому формат здесь короткий — это не ограничение, а
требование, при котором сообщение вообще доходит.

## Быстрый старт

Нужен Python 3.11 или новее. Проверено на 3.14.7.

```bash
git clone https://github.com/petrles444-source/golos-assistent.git
cd golos-assistent

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux и macOS

pip install -r requirements.txt

python golos_servis.py          # запустить службу
```

Отдельное окно — и уже работает:

```bash
python govori.py "Проверка. Если это слышно, всё готово." --играть
```

Ничего скачивать дополнительно не нужно: четыре голоса уже лежат в
папке `modeli`.

## Подключить своего агента

Агенту не нужен Python. Служба говорит по обычному HTTP, поэтому её
понимает что угодно: Node.js, Go, PowerShell, оболочка агента на любом
языке.

Два адреса:

| Адрес | Что делает |
|---|---|
| `GET /state` | жив ли сервис и какие голоса есть |
| `GET /say?агент=IRINA&текст=Привет&играть=0` | произнести фразу |

Те же адреса есть и по-русски: `/состояние` и `/сказать`. Латинские
придуманы для клиентов, которые не умеют кириллицу в адресе: часть
HTTP-библиотек на этом падает с ошибкой кодировки.

Готовый пример на Python: [`primer/primer_python.py`](primer/primer_python.py)
Описание протокола целиком: [`primer/protokol.md`](primer/protokol.md)

Минимальный вызов на любом языке:

```
GET http://127.0.0.1:18905/say?агент=IRINA&текст=Готово&играть=0
```

Ответ — JSON:

```json
{
  "ок": true,
  "файл": ".../озвучка/IRINA.wav",
  "байт": 260140,
  "озвучка_секунд": 5.9,
  "синтез_секунд": 1.93,
  "всего_секунды": 6.63,
  "движок": "piper «irina»",
  "плеер": "не играл",
  "из_кэша": false,
  "скорость": 1.0
}
```

`озвучка_секунд` — это длина самого звука, а `синтез_секунд` — сколько
времени заняло произнесение. Это разные числа, и путать их нельзя: фраза
может произноситься за две секунды, а звучать пять. Для офлайн-голосов
длина снимается точно по заголовку файла; для сетевых голосов в формате
mp3 точно посчитать нечем без декодера, и там будет `null`.

Служба слушает **только 127.0.0.1**. Из интернета она недоступна: так
задумано, голосовая служба не должна быть видна наружу.

## Голоса

Ключи в конфиге — это коды голосов, а не имена людей. Кто каким голосом
говорит, решается одним файлом `golos_stuydii.json`, руками, без
перезапуска кода.

| Код | Голос | Движок | Интернет |
|---|---|---|---|
| `IRINA` | женский, тёплый | piper, модель в репозитории | не нужен |
| `DENIS` | мужской, ровный и спокойный | piper, модель в репозитории | не нужен |
| `DMITRI` | мужской, нейтральный | piper, модель в репозитории | не нужен |
| `RUSLAN` | мужской, второй дополнительный | piper, модель в репозитории | не нужен |
| `SVETLANA` | женский, качество выше | Microsoft | нужен |
| `DMITRY` | мужской, качество выше | Microsoft | нужен |
| `SVETLANA_VYSOKO` | женский, повыше | Microsoft | нужен |
| `SVETLANA_NIZKO` | женский, пониже | Microsoft | нужен |

Проверено наголову: у Microsoft всего два бесплатных русских голоса без
подписки, а разных голосов нужно больше. Поэтому один голос разведён на
две высоты: `+8` и `-12` герц. Разница слышна в первые секунды, даже не
глядя в экран.

**Если сети нет**, а выбран сетевой голос, служба не замолкает: она
берёт офлайн-голос `IRINA` и говорит им. Тишина в ответ хуже ответа
повышенным голосом.

Добавить свой голос — скопируйте любой блок в `golos_stuydii.json` и
поменяйте имя. Больше ничего править не надо.

---

## Правила, которые соблюдаются сами

* **Сообщение начинается с имени.** Имя подставляется автоматически,
  если текст ещё не начинается с него. Отключается ключом `--без-имени`.
* **Длина от 3 до 25 секунд.** Вне окна — честная пометка, а не молчание.
* **Темп словами:** медленно 0.75, нейтрально 1.0, быстро 1.25.
  По умолчанию нейтрально.
* **Повтор звучит одинаково:** ответ кэшируется, поэтому вторая одинаковая
  фраза не синтезируется заново.

Программа `govori.py` следит за именем, длиной и темпом. Если агент
обращается к службе напрямую по HTTP, эти правила он соблюдает сам.

## Устройство

```
golos_servis.py   служба: маршруты, синтез, кэш, выдача звука
govori.py         озвучка текста: имя, длина, темп
golos_stuydii.json конфиг: коды голосов, движок, высота, скорость
modeli/           четыре модели piper, около 60 МБ каждая
primer/           пример подключения и описание протокола
instrumenty/      приборы для проверки
```

Модели грузятся **по первому обращению**, а не все сразу: пока служба
молчит, она почти не занимает память. Первый раз новым голосом —
несколько секунд ожидания. Вернуть загрузку всех голосов при старте —
`python golos_servis.py --сразу`.

Скорость при этом не страдает: у движка на каждую модель ставится один
поток. Проверено измерением — разница между одним и восемью потоками
0,113 против 0,116 секунды на фразу, то есть шум.

Скорость в популярных системах задаётся **до** загрузки движка, потому
что движок читает её один раз при импорте. Поставишь позже — уже поздно.

## Кэш

Ключ кэша — текст, голос, скорость и движок. Тот же текст тем же голосом
и той же скоростью всегда даёт тот же файл.

Голосовые сообщения короткие и повторяющиеся, поэтому на повтор ответа
почти не нужно времени: файл уже готов.

Файл считается годным кэшем, только если он больше 1000 байт. Пустой или
обрезанный файл никогда не будет выдан за готовый ответ.

## Приборы

Проверять голосовой сервис надо живым запросом, а не чтением кода.
«Процесс запустился» ещё ничего не значит.

| Прибор | Что меряет |
|---|---|
| `proverka-golosovoy-sistemy.py` | полная проверка живыми запросами: состояние, озвучка, кэш, повтор, длина |
| `mer-skorost.py` | скорость синтеза по нескольким фразам |
| `mer-modeley.py` | сколько занимает загрузка каждой модели |
| `mer-pamyati.py` | растёт ли память на каждый запрос. Рост — это утечка; нулевой наклон означает, что утечки нет |

Запуск:

```bash
python instrumenty/proverka-golosovoy-sistemy.py
python instrumenty/mer-skorost.py
```

Приборы умеют говорить «не измерено» и выходить с кодом ошибки, если
замер сорвался. Прибор, который сказал бы «нормально», не измерив
ничего, хуже отсутствующего.

---

## Что измерено, а что нет

Измерено на машине, где система работала:

* утечки памяти нет: прирост 0,0 байт на запрос, дважды, до 60 запросов;
* память уменьшена ограничением потоков, скорость при этом не изменилась;
* ленивая загрузка голосов экономит память, пока служба молчит, и съедает
  её больше, когда заговорили все голоса сразу — цифры и вывод записаны
  в коде рядом с настройкой, чтобы решение не «поправили» молча;
* синтез повторной фразы берётся из кэша.

Чего **нет** и не будет выдумано:

* сколько человек реально слушает голосовые сообщения — счётчика
  прослушиваний нет;
* «эффективность выросла на столько-то процентов» — это не измерялось;
* сравнение качества голосов по опросу слушателей — такого опроса не было.

В этой же честности причина двух чисел в коде, которые расходятся между
собой: замеренная скорость синтеза и скорость, записанная в описании
файла при другой настройке. Они не сведены в одно число, и обе цифры
подписаны как разные вещи. Сводить их надо повторным замером, а не
красивым округлением.

## Ограничения

* **Только синтез.** Служба не слушает и не распознаёт речь: микрофон —
  это отдельная задача, и в этот проект она не входит.
* **127.0.0.1.** Снаружи служба недоступна. Это осознанно.
* **Два голоса требуют сети.** Без сети работают четыре офлайновых, и
  служба переключается на них сама.
* **Windows проверен на практике.** Плеер использует системный звук;
  на других системах команда проигрывания может отличаться — код честно скажет
  об ошибке, а не промолчит.
